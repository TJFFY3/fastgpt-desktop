# FastGPT Desktop：对话过程、文件工作区与语音输入设计

日期：2026-09-28。状态：交互方案已获用户确认；本文待用户审阅，尚未进入实现计划或产品代码实现。

## 1. 目标、已确认选择与交付边界

让当前桌面聊天成为可观察、可处理项目文件的 Agent 工作界面：用户能查看真实执行过程，选择文件和工作目录，在本地隔离环境中执行命令，以语音输入文字，并在同一会话中选择模型。

用户已确认：

- 继续使用 Electron + React + TypeScript，沿用现有模型、会话和受控 Agent 基础。
- 保留用户消息靠右、Agent 回复靠左，不增加“用户 / FastGPT Agent”身份标签。
- 展示模型服务实际提供的思考内容、执行命令、实时输出及实时耗时。
- 增加文件选择/拖拽、目录选取、语音输入和模型选择。
- 工作区采用可读写、可执行的本地 Docker 沙箱，不是只读文件浏览器。
- 语音采用可配置的远程识别服务，可使用云服务或自托管服务，不安装离线识别模型。
- 原目录不直接挂载到容器；在隔离副本中修改，预览后经确认写回或导出。
- 命令执行前确认；默认不联网；语音转写进入可编辑输入框，不自动发送。

本文对操作细节作出明确的首版默认值，供本次书面审阅确认。下面的资源上限是产品策略，不代表所有模型或服务都支持相同能力。

本次范围是以上功能的可用闭环，包括持久化、授权、错误处理和测试，不只是增加按钮。原七项需求中的上下文压缩、长期记忆、FastGPT 工作流/Agent、双版本 SSO 和 Skill 管理仍按[原架构设计](2026-09-28-fastgpt-desktop-agent-design.md)推进；本次不将这些未实现能力标记为完成。文件上下文预算检查不等于自动压缩或长期记忆。

## 2. 当前基础与方案选择

现有代码已经具备多个 Chat Completions 模型配置、SQLite 会话/运行记录、SSE 文本和工具调用、可信 Agent 编排进程、窄业务 IPC、取消和中断恢复。当前只有只读时间工具，没有文件、命令、附件、语音或公开思考事件；会话创建后不能切换模型，麦克风权限目前全部拒绝。

工作区方案比较：

| 方案 | 文件影响 | 取舍 |
| --- | --- | --- |
| 隔离副本 + 本地 Docker（采用） | 操作副本，原文件仅在用户明确确认后写回 | 需要导入、检查点和差异预览，能将命令执行与原目录修改分开授权 |
| 直接读写挂载原目录 | 容器命令立即修改原文件 | 同步简单，但确认发生前原文件就可能被修改，不采用 |

单个交付由四个有明确边界的模块构成：执行轨迹与模型切换、附件管理、Docker 工作区、远程语音输入。它们通过现有会话、运行和授权契约组合；不重写 Agent 核心，不增加通用宿主机 shell 或文件 IPC。

## 3. 架构与接口边界

```text
React：聊天气泡 / 执行过程 / 附件 / 工作区面板 / 模型选择 / 录音
    │ 窄业务 IPC；有界音频和文件数据；持久化运行事件
Electron 主进程：身份、凭据、会话、授权、文件选择、导入与导出
    ├── AttachmentService → 本应用管理的附件副本与元数据
    ├── WorkspaceService → 授权源目录、检查点、差异与写回
    ├── SandboxProvider → 本地 Docker → 独立容器工作区
    ├── TranscriptionService → 单独配置的远程音频转写服务
    └── 可信 Agent 编排进程 → 模型适配器 → 文本/思考/工具事件
                                   │ 工具提议
                         ToolGateway → 授权 → 沙箱或受控读取
```

模块职责：

- `packages/shared`：严格验证附件、工作区、授权、音频请求和新增事件；新增字段向旧配置提供明确默认值。
- `packages/storage`：会话、运行、消息和模型快照的事务关联；工作区、附件、授权和语音非敏感配置按身份隔离。
- `packages/model-adapter`：保持 Chat Completions 基线，增加可配置的公开思考字段和独立音频转写适配器；密钥不进入 UI DTO。
- `packages/agent-core`：转发思考/工具事件并等待受控工具执行；不直接读本机目录、操作 Docker 或录音。
- 新的 `packages/sandbox`：Docker 检测、已拥有容器的生命周期、安全参数、输入输出传输、进程和资源限制；提供可替换 Provider 接口，但本次只实现本地 Docker。
- 桌面主进程的工作区、附件和转写服务：负责 OS 交互与权限，Renderer 只持有业务 ID，不持有任意宿主机操作能力。
- Renderer 拆分录音控制、附件状态、运行轨迹和工作区组件，避免全部逻辑堆入 `App.tsx`。

`DesktopApi` 新增专用业务操作：选择/导入附件、选择工作目录、查看工作区条目和差异、确认写回/导出、响应待授权工具、保存转写配置、提交/取消录音转写。不得公开任意 Docker 参数、通用命令执行、路径读取或通用 IPC。

身份、会话、运行、工作区和授权归属均在主进程再次核验。模型和 Skill 内容不参与授权决策；仅凭界面传入的 ID 或路径不能取得权限。

## 4. 对话与输入界面

### 4.1 布局

- 聊天气泡保留现有左右布局和无角色标签展示。
- 每次运行在对应左侧回复区域显示可折叠“执行过程”，而不是把所有历史工具混在页面底部。
- 摘要行显示运行状态、总耗时和步骤数；展开后按事件顺序显示公开思考、待确认操作、命令和结果。
- 输入框下方放文件、工作目录、麦克风和模型选择；发送前上方展示附件名称、大小、处理状态和移除入口。
- 工作区使用可收起面板展示源目录名称、隔离副本状态、文件树、改动和导出入口；容器只看到相对路径，不看到真实宿主机路径。
- 长文本、命令和路径可换行或横向滚动，不撑破聊天列。状态不用颜色单独表达，操作具备可访问名称。

### 4.2 输入状态

- 保留 Enter 发送、Shift+Enter 换行及中文输入法组合保护。
- 只有文本或至少一个可发送附件时才能发送；附件尚在导入/失败时阻止发送，并指向具体失败项。
- 同一会话已有活动运行时，禁止再次发送、切换模型、更换工作区或写回；停止按钮继续可用。
- 会话切换后保留各自草稿和附件状态，不把旧会话上传结果或转写结果放入新会话。
- 活动录音或转写时切换会话会取消该语音操作并释放麦克风；取消后的迟到结果不得修改任何草稿。

## 5. 公开思考、命令与计时

### 5.1 思考内容

- 首版支持显式模型能力设置：不读取思考字段（默认）或读取 Chat Completions 的 `reasoning_content` 字符串字段；同时处理非流式和 SSE 增量。
- UI 标注这是服务返回的内容，不承诺取得所有模型的内部思考。服务未返回时只显示“模型处理中”，不编造推理过程。
- 公开思考单独进入运行轨迹，不当作最终回答，也不自动拼接进下一轮模型消息。
- 现有工具调用、文本增量和结束协议仍需严格验证；开启思考字段不放宽其他协议校验，不向模型新增要求泄露内部推理的指令。
- 思考输出累计最多 1 MiB；超限保留有界内容并明确标记截断，不影响最终回答的正常显示。

### 5.2 事件与历史

新增事件语义包括公开思考增量、待授权操作与授权结果、命令输出增量、步骤结束信息和工作区检查点。事件由可信层绑定 `runId`、`sessionId`、递增序号和时间；命令事件另带工具调用 ID、输出通道、退出码和截断标记。

事件先持久化，再发布并向 Worker 确认；输出按有界块合并，背压防止无限事件队列。所有文本按纯文本渲染，不解释为 HTML、ANSI 控制操作或新授权。

每条新消息显式关联产生它的 Run。历史回看按该关联展示模型、思考和命令，不能用相近时间猜归属。已提交的中间回复在后续工具请求期间继续显示，流式草稿不覆盖先前消息。

终态及工具结果采用持久化的真实记录；没有结束事件的工具显示“已中断 / 结果未知”，不显示成功。应用重启后恢复已保存轨迹，禁止自动重放命令。

### 5.3 耗时语义

- 总耗时从 Run 创建开始到进入终态结束，包含排队、等待用户授权和模型等待；UI 明确叫“总耗时”。
- 命令耗时从实际执行开始到执行结束，不包含用户审阅授权的时间；等待状态单独显示。
- 执行中每秒刷新显示；权威起止时间和耗时由主进程/Provider 产生，终态后冻结。
- 运行进程内用单调时钟计算耗时，在阶段转换及每 5 秒保存耗时检查点；系统时钟调整不能产生负值。重启后的中断记录显示最后确认的已记录耗时，不把关机时间计入执行时间；这些检查点不是虚构的执行进度事件。

## 6. 附件与模型上下文

### 6.1 文件选择与本地导入

- 支持系统多文件选择和拖拽普通文件，草稿最多 16 个附件、单文件最多 20 MiB、单次合计最多 100 MiB；工作区累计限制仍需同时满足。
- 拖拽来源必须在可信 preload/主进程转换为一次性输入授权，不能把 Renderer 声称的任意路径直接当成授权。
- 首版不把 ZIP 自动解压，不接受目录拖拽、链接、设备文件或跨平台路径碰撞；目录通过独立工作区选择流程处理。
- 可信层复制实际选中的字节到应用管理的区域，记录大小、内容 hash、源文件名和业务 ID。发送和历史读取使用该快照，源文件事后变化不会改变已发送内容。
- 附件 DTO 不携带应用密钥或凭据引用，不在日志输出文件全文。移除草稿附件释放未使用副本；已发送附件仍用于历史，不因草稿移除丢失。

### 6.2 “上传”的实际含义

本地导入与发送给远程模型是两个动作。选择文件只产生本地副本；点击发送前展示将离开本机的内容和目标模型服务。

首版内容处理边界：

- UTF-8 文本、Markdown、JSON、CSV 和代码文件可按文本读取并用于上下文；拒绝将明显二进制数据误当文本。
- 图片、PDF、Office 文件和其他二进制文件可以作为沙箱输入，但本次不增加视觉输入、OCR 或通用文档解析。UI 明确提示“已作为工作区文件添加，未提取正文”；不能声称仅凭文件名模型就已理解内容。
- 工具可在本地处理其他格式，但只能用沙箱已安装能力并经过同样的命令授权；不自动联网安装解析器。
- 文件读取限制为单次 64 KiB，并提供偏移和剩余大小；超过范围明确标记，允许后续受控分段读取，禁止静默截断后声称已读完整文件。
- 发送前对文本、附件摘录、完整消息历史、工具定义和输出预留做保守预算检查；超预算要求缩小输入、创建新会话或换模型，不破坏原历史和工具配对。
- 没有工具能力的模型可以聊天和接收预算内文本附件，但不能宣称会执行二进制文件处理或工作区命令。

工作区中已有的文件不自动全量发送给模型。已明确授权的读取工具在读取前展示将发送的相对路径和范围，由用户确认；其返回内容会进入当前模型上下文。上下文来源始终标记为低信任任务材料，文件指令不能提高授权。

## 7. 工作目录、修改与写回

### 7.1 工作区绑定和导入

- 不选目录时，每个会话仍可以拥有独立空工作区，接收显式附件。
- 选择目录后先显示过滤结果、文件数量和总大小，再由用户确认导入；选择动作本身不开始全量复制或上传。
- 默认排除 `.git`、依赖/构建缓存及常见认证材料；展示排除清单。凭据存储、应用认证配置、系统目录、文件系统根和用户主目录不能作为工作区根，不能通过链接绕过。
- 导入普通文件和目录，拒绝符号链接、硬链接、特殊文件、路径穿越、大小写/规范化碰撞；源文件读取期间变化则拒绝该文件并允许重选。
- 工作区最多 10,000 个条目（包括普通文件和目录）、总内容最多 1 GiB、单文件最多 100 MiB。目录清单读取也受此数量限制，不先无限扫描再校验。
- 会话与工作区一对一，按实例/账号/团队隔离。未绑定源目录的空工作区可首次绑定；已有源目录的会话更换目录必须创建新会话，不暗中迁移授权。
- 导入基线记录每个文件的 hash。后续容器只收到隔离副本；真实源路径仅保存在可信主进程的本地元数据中。

### 7.2 检查点与改动

每次有写入可能的工具操作使用当前检查点创建独立容器工作副本。命令及其后台子进程结束、文件传输通过验证后，才原子提交新检查点；下一条工具操作从新检查点继续。

读取不触发新的可写执行。工作区只保留导入基线和最新检查点，不保存无上限全量快照；单个工作区原始内容总量上限为 1 GiB，基线、当前版本和原子提交临时空间最多需要约 3 GiB 本地磁盘，空间不足拒绝提交并保留旧版本。

命令非零退出仍如实显示退出码；用户已授权该命令且产物通过校验时，保存其可能产生的改动。超时、取消、容器崩溃或无效传输不提交不完整检查点；保留上一个检查点，并明确说明本次未提交的文件变更可能丢失。原目录始终不受这些失败影响。

### 7.3 写回和导出

- 差异视图显示新增、修改、删除以及无法按文本展示的二进制改动，不能把二进制“无预览”误标为无变化。
- 写回是可信层执行的独立用户操作，不是 Agent 工具。用户选择具体条目和目标，确认后才开始；删除原文件需要单独明确确认。
- 写回前核验原文件 hash 与导入基线；外部修改形成冲突，不静默覆盖，允许跳过或另存。
- 相对路径、父目录和实际目标都必须核验，拒绝链接和越界。使用安全文件句柄和同目录原子替换，不能只依赖字符串前缀；无法保证目标身份稳定的平台操作拒绝写回，提供另选位置导出。
- 覆盖或删除前保留原文件备份并返回恢复信息；每个工作区备份累计最多 1 GiB，超限则拒绝继续写回，允许用户改为另存或明确管理旧备份，不静默删除备份。每个文件原子处理，多文件写回不是整目录事务；中途失败展示每个条目的实际结果和可恢复备份。
- 另存/导出同样经系统选择器明确目标并确认覆盖，只输出用户选择的普通文件，不包含应用凭据存储、授权记录或未选择的工作区材料。
- 写回不会重新授权源目录中的新增文件；重新导入仍需要用户确认。备份和隔离副本不会作为模型输入自动发送。

## 8. Docker 执行与授权

### 8.1 运行环境

- 仅使用用户机器的本地 Linux 容器引擎；检测当前 Docker 上下文，拒绝把文件静默传到远程引擎。Docker 不可用时文件管理、普通聊天和语音仍可使用，命令工具禁用，绝不回退宿主机 shell。
- 使用应用维护的可信沙箱镜像和固定镜像内容 ID，包含命令解释器、Python、Node 和受控文件传输帮助程序。镜像准备需要显式操作与进度，构建/获取失败不开放执行；命令期间不拉镜像，不自动安装运行时。
- 固定非 root UID/GID、`cap-drop ALL`、`no-new-privileges`、只读根文件系统、独立 PID/IPC/cgroup、默认 seccomp，禁止 privileged、host namespace、宿主机目录、设备和 Docker socket 挂载。
- 仅专用 `/workspace` 和有界临时区域可写。默认 `network none`，不映射端口、不转发代理和密钥环境变量；本次没有启用网络的开关。未来受控出口代理按原架构另行交付。
- 信任边界：Docker 共享内核，不宣称等同 VM；本设计不防御已控制宿主机或 Docker daemon 的攻击者，也不宣称本地文件内容加密。

### 8.2 实际资源限制

沿用原架构上限：每个容器 2 CPU、1 GiB 内存、128 个进程、单命令 120 秒、stdout/stderr 合计最多 1 MiB，工作区最多 1 GiB。容器使用有限 tmpfs 工作区，临时区另外限制为 64 MiB，工作区 inode 上限为 16,384；禁止额外 swap 和可无限增长的容器日志，所有输出走有界管道。命令输出超过上限后保留有界前缀并终止该命令，明确显示超限，不继续消耗无限输出。

有限 tmpfs 为本次跨存储驱动的工作区硬上限方案，不能用目录事后统计冒充强制配额。tmpfs 占用计入 1 GiB 容器内存，所以“1 GiB 工作区上限”不是可用空间保证：执行程序和临时区也消耗内存，可能先触发 OOM。启动前检查实际挂载和 cgroup 限制，不支持所需限制时禁止执行并说明具体原因。依据 [Docker tmpfs 文档](https://docs.docker.com/engine/storage/tmpfs/)和 [Docker run 参数](https://docs.docker.com/reference/cli/docker/container/run/)。

通过可信镜像内的固定帮助程序传入/传出普通文件，主进程重新验证相对路径、文件类型、实际字节数量和 hash，不直接将容器提供的归档解压到宿主机。文件传输通道与命令文本输出分开，受工作区总量、文件大小、条目数量及每阶段 120 秒超时约束；不能通过传输通道绕过 UI/事件输出上限。Docker 的 `cp` 对 tmpfs 等路径有适用限制，因此不能依赖任意 `docker cp` 完成这条数据链。依据 [Docker cp 文档](https://docs.docker.com/reference/cli/docker/container/cp/)。

总并发沙箱最多 2 个，其余等待；用户确认命令后实际执行才开始计命令耗时。取消/超时终止整个对应容器，包含后台子进程，不仅终止客户端连接。仅对所有权 ID 和标签都匹配的本应用资源清理，不运行全局 prune，不删除原目录或其他 Docker 资源。

### 8.3 工具和审批

首版受控工具为：列出已授权工作区文件、分段读取文件、写入隔离文件和执行容器命令。读取文件发往模型、写入副本及执行命令均有明确审批；纯目录清单可以在用户确认工作区导入后读取。单次文本写入最多 64 KiB，命令字符串最多 16 KiB，命令不支持交互式终端、后台常驻服务或自定义 Docker 参数。主进程调用 Docker 使用固定程序和独立参数数组，不启用宿主机 shell；用户批准的命令字符串只交给容器内解释器。

待审批卡展示操作、相对路径、完整命令/参数、数据目的地和隔离说明。批准只针对当前身份、Session、Run、工具调用 ID 和参数 hash；修改参数、切换身份或终态后不能复用。首版不提供“一直允许所有命令”。

流程：完整参数接收与验证 → 预留调用 ID → 持久化待审批 → `waiting_approval` → 用户批准/拒绝 → 再次核验归属与取消 → 执行 → 持久化输出和结果。拒绝产生明确的工具错误结果，允许 Agent 解释或采用其他方案，不自动执行被拒绝操作。

已有调用去重继续有效：已完成调用可以返回原结果，结果未知的调用禁止自动重放。取消会撤销待审批请求并停止正在执行的容器；迟到批准、输出或检查点不能将取消的 Run 改为成功。

## 9. 远程语音输入

### 9.1 配置与协议

增加独立“语音输入”配置：启用状态、服务名称、Base URL、模型 ID、超时、是否明确允许 HTTP 和独立密钥。可以与聊天服务使用相同地址，但不继承聊天配置或密钥，不假设其具备语音能力。

兼容基线为 OpenAI 文件转写协议：向配置 API 根地址拼接 `/audio/transcriptions`，发送 multipart `file` 和 `model`，读取 JSON 的 `text`。支持填写完整转写端点；不自动补 `/v1`，界面展示最终请求地址。第三方云服务或自托管服务必须兼容这条接口；不兼容的专有 ASR 协议不计为已支持。依据 [OpenAI 文件转写文档](https://developers.openai.com/api/docs/guides/speech-to-text)。

首版不发送模型特有的语言/提示/流式参数，不实现 Realtime 持续听写或语音对话。HTTPS 默认、禁止重定向和关闭 TLS 校验；HTTP 需用户明确允许并警告音频与凭据暴露风险。密钥沿用系统安全存储/会话内存策略，Renderer 不拿到已保存的原始密钥。

### 9.2 录音交互与隐私

- 用户点击麦克风才请求系统权限，只允许预期桌面窗口主 frame 的音频录制，不放开摄像头和其他权限；生产与开发分别校验预期 origin。
- 状态为未配置、空闲、录音中、转写中、已取消或失败。展示录音时长及将上传的服务名称；操作为“停止并转写”和“取消”。
- 使用运行环境实际支持的录音格式（WebM/Opus 或 MP4），文件扩展名与实际 MIME 一致；不伪装成 WAV，也不以已支持 API 文件格式推断所有第三方均支持。
- 最长 120 秒、音频最大 20 MiB；超限停止录音并提示，不暗中分片继续上传。权限拒绝、无设备、格式不支持时提供明确反馈，键盘输入保持可用。
- 停止并转写才把本次录音交给主进程；主进程使用受控、可取消、有超时和响应体大小限制的请求。无自动重试或重复上传，用户可明确发起重试。
- 非 JSON、缺失/空文本、超时、认证失败等映射为脱敏错误，不能回显认证头、原始错误 HTML 或密钥。
- 转写文字最多 64 KiB；进入当前会话的语音草稿区域，由用户插入输入框并编辑，不覆盖转写期间输入的文字，不自动发送。
- 原始录音仅临时保留用于本次操作，成功插入、取消、会话切换或退出后清理并释放音轨。默认不把音频保存为历史附件；说明远程服务的数据保留由该服务管理，桌面清理不等于远端删除。
- 异步结果绑定身份、会话和操作代号；会话删除、身份变化和取消后忽略迟到结果并清理临时数据。

真实语音验收需要用户提供有效服务配置。协议模拟服务只能证明请求与 UI 流程，不证明某个聊天网关已经支持 ASR。

## 10. 同会话模型切换与上下文兼容

- 无会话时选择默认模型；空闲会话可以更改下一次运行模型，并保留所有完整历史。
- 主进程事务检查无活动 Run 后更新 Session 的模型引用；界面禁用不是唯一保护。异步读取密钥或文件后启动时重新核验模型版本、会话、工作区和身份，冲突则拒绝启动，不能以旧模型悄悄开始。
- 每个 Run 保存非敏感模型快照：供应商业务 ID、显示名称、模型 ID、协议能力、上下文与输出配置；不保存密钥。修改/删除供应商后，旧运行仍显示真实的当时模型。
- 新运行使用当次固定配置，期间修改模型设置不改变已启动请求。工具能力关闭时不下发沙箱工具；文件读取和命令按钮展示不可用原因。
- 切换到较小上下文窗口时先重新预算；无法容纳则提示，不截断工具调用/结果配对，不删除历史。
- 旧记录迁移不猜模型历史或消息 Run 归属，显示“旧记录未保存模型快照/运行关联”；原消息和工具结果继续可读。

## 11. 数据、安全与失败恢复

新增持久化字段/实体：

| 数据 | 内容与约束 |
| --- | --- |
| Session | 可更新下一次模型、固定工作区业务 ID；保留当前身份命名空间 |
| Run / Message | 非敏感模型快照、显式消息 Run 关联、耗时检查点；旧数据可为空 |
| RunEvent / ToolCall / Approval | 思考、输出、审批、退出码、结果及累计限制；工具 ID 和参数绑定 |
| Attachment / MessageAttachment | 实际文件快照、大小、hash、消息引用和状态；不以用户路径作文件存储键 |
| Workspace / WorkspaceFile | 源目录授权、基线、当前检查点、改动和写回记录；只由可信层操作宿主机路径 |
| TranscriptionConfig | 非敏感服务配置与密钥引用；音频和未发送转写文字不进入运行历史 |

迁移必须事务化并可重复执行，保留全部已有会话、模型、密钥密文和消息。新配置默认不开启思考或语音；旧会话第一次导入文件时才分配工作区，不批量创建 Docker 容器。

附件、文件和事件都是低信任材料。限制 IPC 和 Worker 消息大小，禁止原始 Base64 音频进入日志或运行事件。身份范围始终来自主进程；缓存、审批、音频操作和工作区都以同样命名空间隔离。

重启将活动 Run 标记为 interrupted，撤销审批，清理已拥有的遗留容器，恢复最近检查点，不自动重复命令。单实例所有权在恢复/清理前获得，第二个实例不能破坏正在运行的容器。

删除会话需说明将删除本地消息、附件和隔离副本，先取消相关录音、审批和执行再清理。源目录和已导出文件不删除；写回备份的保留/删除单独告知，避免把可恢复备份随会话一并清掉。清理受文件归属元数据约束，不对模糊路径递归删除。

沙箱失败、语音失败和附件失败互不冒充模型协议错误；错误清楚区分 Docker、授权、文件冲突、模型能力、上下文预算和 ASR 服务，并保留可继续的普通聊天。

## 12. 验收与实施顺序

详细任务与测试代码在本文书面批准后编制实施计划；建议依赖顺序为契约/迁移 → 轨迹与模型切换 → 附件/工作区 → Docker 与审批 → 语音 → 联合验收。

必须覆盖：

1. 公开思考与普通回答分开；不支持思考的模型正常聊天；SSE 跨块、输出上限和异常数据正确处理。
2. 命令真实执行、stdout/stderr 实时显示、退出码准确；总计时含授权等待、命令计时不含等待，终态冻结且重启可回看。
3. 用户右、回复左，无角色标签；多轮工具中间回复不丢失或重复；长内容和窄窗口不溢出，中文输入法行为保留。
4. 空闲切换模型生效并记录每次实际模型；运行期间、异步启动期间和跨会话操作不能穿透锁定或串数据。
5. 选择/拖拽附件、仅附件发送、移除、导入失败、大小和上下文超限、源文件变化、重启历史正确；二进制不伪装成已提取正文。
6. 导入目录过滤、路径/链接/类型/数量拒绝正确；不同身份/会话不能相互读取工作区；文件读取给模型前的审批有效。
7. 容器实际非 root、根只读、无宿主挂载/socket、网络禁用；CPU/内存/进程/工作区配额、输出超限、超时和后台子进程取消实测有效。
8. 改动和二进制差异可见；检查点跨工具/运行保留；取消或异常不提交不完整版本；冲突写回不覆盖外部修改，删除/覆盖需确认，备份可恢复。
9. Docker/镜像缺失不退回宿主执行；镜像准备和清理只处理本应用资源；第二个应用实例不干扰当前资源。
10. 麦克风权限只给明确的音频请求；录音可停/取消，发送目标可见，转写可编辑且不覆盖草稿；会话切换和迟到结果不串入新会话。
11. ASR 独立配置、multipart 实际格式、取消、超时、错误响应和密钥保护；使用真实麦克风及用户指定服务完成独立验收。
12. 从现有真实数据结构迁移后历史完好；类型检查、单元测试、真实 Electron E2E、生产构建和安全回归通过。

普通模型/ASR 协议测试使用本地受控服务和临时数据目录，不读取或调用用户已保存的真实凭据。Docker 集成测试使用带测试归属标签的资源，并在结束后只清理这些资源。当前机器能进行 macOS + Docker Desktop Linux 容器验证；Windows/Linux 未实机验证的部分必须在交付说明中标记，不能由单平台通过推断。

## 13. 书面审阅检查

- 功能与用户确认的交互一致；无宿主机命令、目录自动上传、后台监听或自动发送。
